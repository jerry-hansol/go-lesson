코드 리딩 플레이북 — 낯선 Go 코드베이스 여는 법

처음 보는 Go 프로젝트를 체계적으로 파악하는 5단계. 실전 적용 예시는 레슨 0014 (mediamtx 투어).

5단계 절차

단계하는 일근거 레슨
① 진입점부터main.go를 찾아 초기화 순서를 읽는다. 좋은 프로젝트일수록 main은 짧고, 진짜 조립은 한 단계 아래(예: internal/core)에 있다.0001
② 디렉토리 지도코드를 읽기 전에 ls/tree -L 2로 지도를 그린다. 디렉토리 = 패키지 = 책임 하나. internal/은 외부 import 금지 구역이다.0008
③ 인터페이스가 경계grep -rn "interface {"로 핵심 인터페이스부터 찾는다. 인터페이스는 모듈 경계·교체 지점·테스트 심(seam)이 모이는 곳이고, Go에선 사용하는 쪽이 정의한다.0006
④ 데이터의 여정 하나대표 시나리오 하나(연결 수립→처리→종료)를 진입점부터 끝까지 추적한다. 전체를 다 읽으려 하지 말 것 — 한 여정이 아키텍처를 드러낸다.0007
⑤ 테스트가 사용 설명서*_test.go는 "이 API를 이렇게 쓴다"의 실행 가능한 예제집이다. 문서가 없어도 테스트는 거짓말하지 않는다.0009

손에 익힐 명령

명령용도
head go.mod모듈명·Go 버전 — 신원 확인
grep -rn "interface {" internal/경계(인터페이스) 목록 뽑기
grep -rn "func main(" .진입점 찾기 (cmd/ 여러 개일 수 있음)
grep -rn "go " --include="*.go" | grep -v _test고루틴이 태어나는 곳 = 동시성 구조
go doc ./internal/stream패키지 공개 API 요약
git log --follow -- <파일>파일의 변경 이유(커밋 메시지) 추적

읽을 때의 규율

  • 넓게 → 좁게. 지도 없이 파일 하나를 정독하지 말 것. 미아가 된다.
  • 가설을 세우고 grep으로 검증. "publish는 pathManager로 갈 것이다" → 찾아서 확인. 추측만 하고 넘어가면 배운 게 없다.
  • 버전을 기록. 코드 리딩 노트에는 커밋/태그를 남긴다 — 구조는 바뀐다.
  • 막히면 이슈·PR 검색. 그 코드가 왜 그렇게 생겼는지는 종종 리포의 토론에 있다.
