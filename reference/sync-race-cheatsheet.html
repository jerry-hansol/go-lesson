동기화·레이스 치트시트

공유 상태 보호의 최소 패턴. 출처: Go by Example: Mutexes, Go Race Detector, Effective Go.

표준 골격 — 구조체 + 뮤텍스 + 맵

type Store struct {
    mu      sync.Mutex        // 보호 대상 필드 바로 위에
    viewers map[string]int
}

func (s *Store) Add(stream string, n int) {   // 반드시 포인터 리시버
    s.mu.Lock()
    defer s.mu.Unlock()                       // Lock 직후 defer 예약
    s.viewers[stream] += n
}
  • 읽기 >> 쓰기면 sync.RWMutex: 읽기는 RLock()/RUnlock() (동시 허용), 쓰기는 Lock().
  • Go 뮤텍스는 재진입 불가 — 같은 고루틴의 이중 Lock은 자기 데드락.
  • sync.Once: 딱 한 번 초기화. sync/atomic: 단일 정수 카운터의 경량 대안.

레이스 디텍터

명령용도
go run -race .실행하며 레이스 검출
go test -race ./...테스트 전체를 레이스 검사와 함께 (CI 권장)
  • 검출 시 WARNING: DATA RACE + 읽기/쓰기 고루틴의 파일:줄 스택, 종료 코드 66 (Found N data race(s)).
  • 오버헤드(실행·메모리 수 배) 때문에 개발·CI 전용 — 프로덕션 빌드 금지.
  • 실제로 실행된 경로의 레이스만 잡는다 — 테스트가 그 경로를 밟아야 한다.
