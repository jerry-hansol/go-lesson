Go 에러 처리 치트시트

만들고, 감싸고, 검사하고, 정리하는 패턴 전부. 출처: Errors are values, Go by Example: Errors.

기본 리듬 — 조기 반환

w, h, err := parseResolution(s)
if err != nil {
    return fmt.Errorf("스트림 설정 실패: %w", err)  // 맥락 붙여 위로
}
// 성공 경로는 들여쓰기 없이 계속
  • 성공이면 err == nil. 에러면 나머지 반환값은 쓰지 않는 것이 관례.
  • 받은 err를 안 쓰면 declared and not used 컴파일 에러 → 무시가 어렵다.

에러 만들기

패턴쓰임
errors.New("고정 메시지")단순 에러. 패키지 레벨 sentinel(var ErrNotFound = errors.New(...))로도 사용
fmt.Errorf("세션 %d 없음", id)포맷이 필요한 에러
fmt.Errorf("...: %w", err)래핑 — 원인 에러를 체인에 보존. 위로 전달할 때 기본값

에러 검사

패턴쓰임
if err != nil실패 여부만 — 90%는 이것
errors.Is(err, ErrX)래핑 체인에 특정 에러(sentinel)가 있는지
errors.As(err, &target)체인에서 특정 타입의 에러 꺼내기 (구조체·인터페이스 학습 후)

⚠️ %v로 포맷하면 체인이 끊겨 errors.Is가 못 찾는다. 원인 보존이 필요하면 반드시 %w.

defer — 정리 예약

f, err := os.Open(path)
if err != nil {
    return err
}
defer f.Close()    // 연 직후에 닫기 예약 — 어떤 return 경로든 실행됨
  • 실행 시점: 감싼 함수가 리턴하기 직전. 여러 개는 역순(LIFO).
  • 인자는 defer 문을 만난 시점에 평가된다: 
    n := 1
defer fmt.Println("defer가 본 n:", n)  // → 1이 찍힌다
n = 99                                  // 이미 늦었다

안티패턴

  • _ = err 또는 v, _ := f()로 에러 버리기 — 컴파일러를 이기는 유일한 방법이자 최악의 습관
  • 모든 층에서 로그 찍고 또 위로 반환 — 로그가 중복된다. 처리하거나, 감싸서 반환하거나, 둘 중 하나만
  • panic을 예외처럼 쓰기 — panic은 프로그래머 실수(불변식 위반) 전용. 예상 가능한 실패는 전부 error
