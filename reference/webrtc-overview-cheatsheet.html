offer/answer 4단계 호출 순서

순서피어호출어기면
①제안자CreateOffer → SetLocalDescription—
②응답자SetRemoteDescription(offer)③에서 InvalidStateError: remote description is not set
③응답자CreateAnswer → SetLocalDescription—
④제안자SetRemoteDescription(answer)제안자 have-local-offer에서 정지, 연결 불성립

상태 머신 3개 (독립적으로 돈다)

상태흐름콜백
Signalingstable → have-local/remote-offer → stableOnSignalingStateChange
ICEnew → checking → connected / failedOnICEConnectionStateChange
Connectionnew → connecting → connected / failed / closedOnConnectionStateChange

실무 판정은 Connection의 connected. signaling stable은 "서류 접수 완료"일 뿐이다.

pion 최소 골격 (한 프로세스 두 피어, non-trickle)

pc, err := webrtc.NewPeerConnection(webrtc.Configuration{})
// 콜백 등록: OnConnectionStateChange / OnDataChannel / OnTrack(0018)

offer, err := pc.CreateOffer(nil)
g := webrtc.GatheringCompletePromise(pc)   // non-trickle: 수집 완료 대기
err = pc.SetLocalDescription(offer)
<-g
// pc.LocalDescription()을 상대에게 전달 (시그널링) → 상대의 answer를 SetRemoteDescription
