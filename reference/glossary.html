Reference · Glossary

Go 용어집

레슨에서 확정한 용어와 정의. 모든 레슨은 이 용어집의 어휘를 따른다. 새 용어는 첫 등장 레슨과 함께 추가된다.

패키지 (package)
Go 코드의 기본 묶음 단위. 같은 디렉토리의 .go 파일들은 같은 패키지에 속한다. Java의 package와 달리 디렉토리 = 패키지가 강제된다. — 레슨 0001
main 패키지 / main 함수
실행 바이너리의 진입점. package main을 선언한 패키지의 func main()에서 프로그램이 시작한다. Java의 public static void main에 해당하지만 클래스가 없다. — 레슨 0001
모듈 (module)
버전 관리·배포의 단위. 여러 패키지를 담는 트리이며, 루트의 go.mod 파일로 정의된다. Java의 Maven/Gradle 프로젝트에 대응하지만 설정이 훨씬 가볍다. — 레슨 0001
go.mod
모듈의 이름(모듈 경로), 요구 Go 버전, 의존성 목록을 기록하는 파일. go mod init <이름>으로 생성한다. — 레슨 0001
gofmt
공식 코드 포매터. 포맷 스타일 논쟁을 언어 차원에서 종결했다 — 모든 Go 코드는 gofmt 출력 그대로 쓴다. go fmt ./...로 실행. — 레슨 0001
정적 바이너리 (static binary)
go build가 만드는, 런타임(JVM 같은 것) 없이 단독 실행되는 하나의 실행 파일. 컨테이너 이미지가 작아지고 배포가 단순해진다 — 미디어 서버들이 Go를 택하는 이유 중 하나. — 레슨 0001
GOPATH
모듈 도입(Go 1.11+) 이전의 소스 배치 방식. 오래된 글에서만 만나는 과거 유물 — 지금은 신경 쓰지 않아도 된다. — 레슨 0001
zero value
선언만 하고 초기화하지 않은 변수가 갖는 타입별 기본값 — 숫자는 0, 문자열은 "", 불리언은 false. Go에는 "초기화 안 된 변수" 상태가 없다. — 레슨 0002
짧은 변수 선언 (:=)
함수 안에서 선언과 초기화를 한 번에 하는 문법. 타입은 초기값에서 추론. 패키지 레벨(함수 밖)에서는 쓸 수 없다. — 레슨 0002
타입 변환 (conversion)
T(v) 형태의 명시적 변환. Go에는 Java 같은 암묵적 숫자 승격이 없어, 타입이 다르면 연산이 컴파일 에러가 된다. — 레슨 0002
다중 반환 (multiple return values)
함수가 값을 여러 개 반환하는 기능. (값, error) 에러 처리 관례의 토대가 된다. — 레슨 0002
블랭크 식별자 (_)
값을 받되 버리는 자리표시자. 안 쓰는 변수가 컴파일 에러이기 때문에, 필요 없는 반환값은 _로 명시적으로 버린다. — 레슨 0002
error 인터페이스
실패를 나타내는 내장 타입. 특별한 문법이 아니라 메서드 하나(Error() string)짜리 인터페이스 값이며, 성공은 nil로 표현한다. — 레슨 0003
(값, error) 관례
실패할 수 있는 함수가 마지막 반환값으로 error를 돌려주는 Go의 표준 시그니처. 호출부는 if err != nil 조기 반환으로 처리한다. — 레슨 0003
에러 래핑 (%w)
fmt.Errorf("맥락: %w", err)로 원인 에러를 체인에 보존하며 맥락을 붙이는 것. %v는 문자열로 녹여 체인을 끊는다. — 레슨 0003
errors.Is
래핑 체인 어딘가에 특정 에러가 있는지 검사하는 표준 함수. sentinel 에러 비교에 쓴다. — 레슨 0003
defer
함수가 리턴하기 직전에 실행되도록 호출을 예약하는 문. 자원을 연 직후 닫기를 예약하는 정리 관례(Java try-with-resources 대응). 여러 개는 역순(LIFO), 인자는 defer 문 시점에 평가. — 레슨 0003
슬라이스 (slice)
배열을 가리키는 (포인터, len, cap) 세 값짜리 창(view). 슬라이싱(s[1:3])은 복사가 아니라 같은 배열 공유. Java ArrayList의 자리를 차지하지만 내부가 훤히 보인다. — 레슨 0004
append
슬라이스에 값을 추가하는 내장 함수. cap을 넘기면 더 큰 배열로 복사하므로 반환값을 반드시 다시 받는다 (s = append(s, x)). — 레슨 0004
맵 (map)
해시맵. 쓰기 전에 make가 필수(nil 맵 쓰기는 panic). 없는 키 읽기는 에러가 아니라 zero value. range 순회 순서는 의도적으로 무작위. — 레슨 0004
comma ok 관용구
v, ok := m[k] — 값과 "존재 여부"를 함께 받는 관용구. zero value 때문에 "값이 0인 키"와 "없는 키"를 구분하는 유일한 방법. — 레슨 0004
for range
Go의 유일한 루프 for의 컬렉션 순회 형태. 슬라이스는 (인덱스, 값), 맵은 (키, 값)을 준다. while도 for로 쓴다. — 레슨 0004
nil
포인터·슬라이스·맵 등 참조류 타입의 zero value. 타입마다 관대함이 다르다 — nil 슬라이스는 append 가능, nil 맵은 쓰기 panic. — 레슨 0004
구조체 (struct)
필드를 묶는 값 타입. 클래스와 달리 상속·생성자·getter/setter가 없고, zero value 상태로 즉시 사용 가능하다. — 레슨 0005
포인터 (pointer)
&로 주소를 얻고 *T 타입으로 원본을 공유한다. Go는 대입=값 복사가 기본이라 공유가 명시적. zero value는 nil이며 역참조 시 panic. 포인터 연산은 없다. — 레슨 0005
리시버 (receiver)
메서드를 타입에 붙이는 func (s *Stream) Start() 문법의 s — Java의 this. 상태를 수정하면 포인터 리시버가 필수이고, 하나라도 포인터면 전부 포인터로 통일한다 (Go FAQ). — 레슨 0005
생성자 관례 (NewX)
언어 차원의 생성자가 없어, 초기화 로직이 필요하면 NewStream(...) 같은 일반 함수를 만드는 관례. zero value로 충분하면 리터럴로 끝낸다. — 레슨 0005
인터페이스 (interface) / 암묵적 구현
메서드 셋의 이름. 타입이 요구 메서드를 전부 갖추면 선언 없이 자동으로 구현된다(암묵적 구현) — Java의 implements가 없다. 인터페이스는 구현하는 쪽이 아니라 사용하는 쪽이 정의하는 것이 관례. — 레슨 0006
io.Reader / io.Writer
표준 라이브러리를 관통하는 메서드 1개짜리 인터페이스. 파일·소켓·HTTP 바디가 전부 이 둘로 통하며, 미디어 서버는 본질적으로 Reader→Writer 파이프라인이다. — 레슨 0006
fmt.Stringer
String() string 메서드 하나로 이루어진 인터페이스. 이를 구현하면 fmt.Println 등이 그 출력을 쓴다 — Java toString()의 대응물. — 레슨 0006
타입 단언 (type assertion)
v, ok := i.(T) — 인터페이스 값에서 구체 타입을 꺼낸다. , ok 형태는 실패를 false로 알려주고, ok 없는 형태는 실패 시 panic. Java의 instanceof+캐스팅 대응물. — 레슨 0006
고루틴 (goroutine)
Go 런타임이 관리하는 초경량 실행 단위. go f()로 시작한다. 초기 스택이 수 KB라 수십만 개도 일상 — OS 스레드(Java Thread)와의 결정적 차이. main이 리턴하면 전부 즉시 종료된다. — 레슨 0007
채널 (channel)
고루틴 사이에 값을 전달하는 타입 있는 파이프. make(chan T)로 생성, ch <- v로 송신, <-ch로 수신. "통신해서 메모리를 공유하라" 철학의 구현체. — 레슨 0007
unbuffered / buffered 채널
unbuffered(make(chan T))는 송수신이 만나야 진행되는 동기화 지점. buffered(make(chan T, n))는 버퍼가 찰 때까지 송신이 블록되지 않는다 — Java BlockingQueue에 대응. — 레슨 0007
close와 range (채널)
close(ch)는 생산자가 "더 안 보낸다"를 알리는 선언. for v := range ch는 채널이 닫히고 소진되어야 끝난다. 닫힌 채널 송신·이중 close는 panic. — 레슨 0007
sync.WaitGroup
고루틴 완료를 기다리는 카운터 — Java CountDownLatch에 대응. Add(go 띄우기 전에)·defer wg.Done()·Wait 3박자. — 레슨 0007
데드락 (deadlock)
모든 고루틴이 서로를 기다리며 멈춘 상태. Go 런타임이 감지해 fatal error: all goroutines are asleep - deadlock!으로 즉사시킨다. 스택의 [chan send] 등이 멈춘 지점을 알려준다. — 레슨 0007
import 경로
모듈 경로 + 디렉토리 경로 (mediakit/internal/segment). 같은 모듈 안이면 go.mod 선언 없이 바로 import된다. 모듈 모드에서 상대 경로 import는 쓰지 않는다. — 레슨 0008
internal 패키지
internal/ 아래 패키지는 그 부모 트리 밖(외부 모듈)에서 import하면 컴파일 에러 — 관례가 아니라 컴파일러가 강제하는 비공개 경계. mediamtx는 코드 전부를 여기에 둔다. — 레슨 0008
cmd/ 레이아웃
바이너리 진입점을 cmd/<이름>/main.go에 두는 표준 관례. 바이너리가 여러 개면 나란히 추가하고 go run ./cmd/<이름>으로 실행한다. — 레슨 0008
exported / unexported
대문자 시작 식별자는 패키지의 public API, 소문자는 내부 전용. 밖에서 소문자 식별자는 "금지"가 아니라 undefined — 보이지도 않는다. 이 이분법이 Go의 캡슐화 전부다. — 레슨 0008
go test
언어 내장 테스트 러너. _test.go 파일의 func TestXxx(t *testing.T)를 자동 발견해 실행한다 — 어노테이션·프레임워크·assert 라이브러리가 없고, 테스트는 대상 코드와 같은 패키지에 둔다. — 레슨 0009
테이블 드리븐 테스트 (table-driven test)
케이스를 구조체 슬라이스(테이블)로 선언하고 range로 돌리는 Go 표준 테스트 패턴. 케이스 추가가 테이블 한 줄이라 유지비가 낮다. 회사 Go 컨벤션의 요구 형식. — 레슨 0009
t.Run 서브테스트
테이블의 각 케이스를 이름 있는 서브테스트로 감싸는 메서드. 실패가 케이스 단위로 보고되고 -run 'Test이름/케이스명'으로 하나만 골라 실행할 수 있다. — 레슨 0009
got / want 관례
테스트에서 실제 값은 got, 기대값은 want로 부르고 실패 메시지도 got X, want Y 순서로 쓰는 표준 어휘. t.Errorf는 기록 후 계속, t.Fatalf는 그 서브테스트 즉시 중단. — 레슨 0009
핸들러 (http.HandlerFunc)
HTTP 요청을 처리하는 그냥 함수 — func(w http.ResponseWriter, r *http.Request). 어노테이션 없이 이 시그니처가 Spring의 컨트롤러 메서드를 대신한다. w는 io.Writer이기도 해서 JSON Encoder가 바로 꽂힌다. — 레슨 0010
ServeMux 패턴 라우팅
표준 라우터. Go 1.22부터 "GET /streams/{id}"처럼 메서드+와일드카드 패턴을 지원하고, 핸들러에서 r.PathValue("id")로 꺼낸다. 등록 안 된 메서드는 405 + Allow 헤더 자동 응답. — 레슨 0010
struct 태그 (json:"...")
필드 뒤 백틱 문자열로 메타데이터를 붙이는 문법 — Jackson 어노테이션의 자리. json:"bitrate_kbps"가 JSON 키를 정하고, ,omitempty는 zero value일 때 키를 생략한다. unexported 필드는 태그가 있어도 조용히 제외된다. — 레슨 0010
json.Encoder / json.Decoder
json.NewEncoder(w).Encode(v) / json.NewDecoder(r.Body).Decode(&v) — io.Writer/io.Reader에 바로 직렬화·역직렬화하는 스트리밍 API. Decode의 error 반환값 확인이 잘못된 입력의 방어선. — 레슨 0010
select
여러 채널 연산을 동시에 기다리는 문. 준비된 case가 실행되고, 여러 개면 무작위(기아 방지), 없으면 블록(default가 있으면 논블로킹). time.After와 조합해 타임아웃 패턴을 만든다. — 레슨 0011
context.Context
요청 하나에 얽힌 고루틴 전부에 취소를 방송하는 트리. Background() 루트에서 WithCancel/WithTimeout으로 파생하며, 부모가 취소되면 자손도 취소된다. 실무 Go 함수 대부분의 첫 인자가 ctx인 이유. Java에 대응물 없음. — 레슨 0011
ctx.Done() / ctx.Err()
Done()은 취소되면 닫히는 채널(select case로 바로 사용), Err()는 취소 사유 — 수동·클라이언트 이탈은 context.Canceled, 시한 초과는 context.DeadlineExceeded. — 레슨 0011
defer cancel() 관례
WithCancel/WithTimeout이 준 cancel 함수는 시한이 지났더라도 반드시 호출해 리소스를 해제한다. 버리면 go vet의 lostcancel 검사가 context leak으로 잡는다. — 레슨 0011
데이터 레이스 (data race)
고루틴 둘 이상이 같은 메모리를 동기화 없이 접근하고 하나 이상이 쓰기인 상태. 크래시가 아니라 조용히 틀린 값을 내며, 타이밍 의존이라 재현이 어렵다. — 레슨 0012
레이스 디텍터 (-race)
go run -race / go test -race로 켜는 내장 검출기. 레이스를 읽기/쓰기 고루틴의 파일:줄까지 짚어 보고하고 종료 코드 66을 반환한다. 오버헤드 때문에 개발·CI 전용이며, 실제 실행된 경로만 검사한다. — 레슨 0012
sync.Mutex / sync.RWMutex
공유 상태의 자물쇠. mu.Lock(); defer mu.Unlock() 관례로 쓰고, 보호 대상 필드 바로 위에 선언해 구조체와 한 몸으로 묶는다. 재진입 불가 — 이중 Lock은 자기 데드락. RWMutex는 읽기 많은 워크로드용(RLock 동시 허용). Java synchronized 대응물. — 레슨 0012
채널 vs 뮤텍스
소유권을 넘기는 파이프라인은 채널, 여러 고루틴이 같은 상태를 짧게 읽고 쓰면 뮤텍스. "통신해서 공유하라"는 소유권 이전 이야기지 모든 공유 상태를 채널로 바꾸라는 뜻이 아니다. — 레슨 0012
graceful shutdown
종료 신호를 받으면 새 요청은 거절하되 진행 중인 작업(요청·워커)은 마저 끝내고 스스로 종료하는 패턴. Go에서는 context 취소 전파 + http.Server.Shutdown + WaitGroup 대기의 조합으로 구현한다. — 레슨 0013
signal.NotifyContext
OS 시그널(SIGINT/SIGTERM)이 오면 자동으로 취소되는 context를 만들어, 종료 신호를 context 세계로 번역하는 표준 함수 (os/signal). 반환된 stop은 defer로 호출한다. — 레슨 0013
인터페이스 임베딩 (interface embedding)
인터페이스 정의 안에 다른 인터페이스 이름을 쓰면 그 메서드 셋을 통째로 포함한다 — Java 인터페이스의 extends에 대응. 예: mediamtx의 Publisher는 Source를 임베딩한다. — 레슨 0014
시그널링 (signaling)
두 피어가 SDP를 주고받는 절차. WebRTC 표준이 의도적으로 정하지 않은 유일한 층 — HTTP, WebSocket, 무엇이든 애플리케이션 몫이다. 실습에서는 한 프로세스 안에서 변수로 전달해 대체했다. — 레슨 0015
SDP (Session Description Protocol)
"나는 이런 통신을 할 수 있다"는 자기소개서 텍스트. m= 라인이 미디어/데이터 섹션을 선언하고 a= 라인들이 속성(fingerprint, ice-ufrag, candidate)을 붙인다. 줄바꿈은 \r\n. — 레슨 0015
offer / answer 모델
제안자가 offer를, 응답자가 answer를 만들어 각자 SetLocalDescription·SetRemoteDescription으로 등록하는 4단계 협상. 순서를 어기면 InvalidStateError — answer는 remote offer 없이는 만들 수조차 없다. — 레슨 0015
PeerConnection 상태 머신
SignalingState(SDP 교환 진행), ICEConnectionState(경로 탐색), PeerConnectionState(종합 판정) 세 개가 독립적으로 돈다. 실무 판정 신호는 PeerConnectionState의 connected — signaling stable은 서류 접수 완료일 뿐이다. — 레슨 0015
ICE (Interactive Connectivity Establishment)
NAT 뒤의 두 피어가 통할 수 있는 경로를 찾는 프레임워크. 양쪽이 candidate를 모아 교환하고, 모든 pair에 연결 검사(STUN 바인딩)를 쏘아 통하는 조합을 선택한다. 상태는 checking → connected로 전이. — 레슨 0016
STUN
"밖에서 너는 이렇게 보여"라고 공인 주소:포트를 알려주는 거울 서버. 트래픽을 나르지 않아 비용이 거의 없다. pion 설정 오타 시 에러 없이 조용히 무시되므로 srflx 부재로 진단한다. — 레슨 0016
TURN
직결이 불가능한 NAT 조합에서 미디어 전체를 중계하는 릴레이 서버 — 최후의 수단. 스트림 대역폭이 곧 서버 비용이라, relay pair 비율이 미디어 서비스의 인프라 비용 지표가 된다. — 레슨 0016
ICE candidate (host/srflx/prflx/relay)
자신이 도달 가능할지 모르는 주소:포트 후보. host=NIC 주소, srflx=STUN이 알려준 공인 주소, prflx=연결 검사 패킷의 출발지에서 역발견된 주소, relay=TURN 할당 주소. — 레슨 0016
trickle ICE
candidate 수집 완료를 기다리지 않고 모이는 대로 상대에게 흘려보내 연결 시간을 줄이는 방식. pion에서는 OnICECandidate로 받아 상대의 AddICECandidate에 넣는 중계로 구현된다. — 레슨 0016
DTLS
TLS의 UDP판. WebRTC의 모든 트래픽(데이터·미디어)이 이 핸드셰이크로 합의한 키 위에서 암호화된다 — 암호화 없는 모드는 없다. 자가서명 인증서를 SDP의 a=fingerprint(지문)와 대조해 신뢰하므로, 신뢰의 뿌리는 시그널링 채널이다. — 레슨 0017
SRTP
미디어(RTP)를 암호화하는 프로토콜. 키는 DTLS 핸드셰이크에서 유도한다(DTLS-SRTP). 데이터는 SCTP로, 미디어는 SRTP로 — 같은 DTLS 위에서 갈라진다. — 레슨 0017
DataChannel (SCTP)
임의의 바이트를 P2P로 보내는 채널. TCP도 UDP도 아닌 SCTP를 DTLS 위에 태운 것 — 한 연결에 독립 스트림 여러 개, 스트림마다 신뢰성 설정 가능. pion에선 CreateDataChannel/OnDataChannel과 OnOpen/OnMessage 콜백으로 다룬다. — 레슨 0017
신뢰성 옵션 (Ordered/MaxRetransmits/MaxPacketLifeTime)
DataChannel별 전송 보장 설정. 채팅·파일은 기본(신뢰·순서), 게임 좌표·실시간 상태는 Ordered:false, MaxRetransmits:0(최신 값만), 시한부 데이터는 MaxPacketLifeTime. 뒤의 둘은 상호 배타. — 레슨 0017
RTP (Real-time Transport Protocol)
UDP 위에서 미디어를 나르는 프로토콜. 전달을 보장하는 대신 수신 쪽이 스스로 복구할 단서(SSRC·seq·timestamp·payload type)를 헤더에 싣는다. — 레슨 0018
RTCP
RTP의 쌍둥이 제어 채널. 수신 품질 보고(SR/RR)와 재전송·키프레임 요청(NACK/PLI)이 다닌다. PLI는 SFU가 새 시청자에게 첫 화면을 주기 위해 필수. — 레슨 0018
SSRC / sequence number / timestamp
RTP 헤더의 3대 필드 — 스트림 구분(SSRC), 유실 감지·재정렬(seq, 패킷당 +1), 재생 타이밍·립싱크(timestamp, 비디오 90kHz 클럭). seq와 timestamp의 시작값은 보안상 난수라 절대값이 아닌 Δ를 읽는다. — 레슨 0018
TrackLocal / TrackRemote
pion의 미디어 송신/수신 API. 보내기는 TrackLocalStaticSample(프레임을 주면 RTP 패킷화까지 pion이)과 TrackLocalStaticRTP(RTP 그대로 — SFU 포워딩용), 받기는 OnTrack 콜백의 TrackRemote에서 ReadRTP(). OnTrack은 협상 완료가 아니라 첫 RTP 패킷 도착 시 불린다. — 레슨 0018
코덱 협상 (a=rtpmap)
동적 payload type 번호(96~127)를 코덱에 매핑하는 SDP 라인 — a=rtpmap:96 VP8/90000. 연결마다 새로 계약하며, pion은 MediaEngine.RegisterDefaultCodecs가 기본 목록을 채운다. 공통 코덱이 없으면 answer 적용 시점에 협상이 실패한다. — 레슨 0018
SFU (Selective Forwarding Unit)
발행자의 RTP를 디코딩·재인코딩 없이 구독자들에게 선별 전달하는 미디어 서버 모델. 발행자는 한 번만 업로드하고 서버가 팬아웃한다. 클라이언트당 PeerConnection 1개. LiveKit·mediamtx WebRTC의 구조. — 레슨 0019
full mesh / MCU
SFU의 두 대안. mesh는 서버 없이 전원 직접 연결 — 참가자당 업로드 N−1개라 소수 인원 전용. MCU는 서버가 모든 스트림을 디코딩→합성→재인코딩 — 다운로드가 1개로 줄지만 서버 CPU가 비싸고 지연이 붙는다. — 레슨 0019
PLI (Picture Loss Indication)
"키프레임을 새로 만들어 달라"는 RTCP 피드백. 새 구독자는 키프레임부터 받아야 화면을 그릴 수 있어, SFU가 구독자 합류 시 발행자 쪽으로 보낸다. pion broadcast 예제는 intervalpli 인터셉터로 주기 전송한다. — 레슨 0019
RTP 포워딩 (TrackLocalStaticRTP)
TrackRemote.ReadRTP()로 받은 패킷을 TrackLocalStaticRTP.WriteRTP()로 다른 연결에 흘리는 SFU의 심장. "Static" = seq·timestamp는 통과, SSRC·페이로드 타입은 연결별 협상값으로 자동 재작성. — 레슨 0019
interceptor (pion)
RTP/RTCP 패킷 경로에 끼어드는 플러그인 체인 — HTTP 미들웨어의 미디어판. NACK 재전송·수신 리포트 같은 RTCP 자동화가 전부 이걸로 구현되어 interceptor.Registry에 등록된다. mediamtx는 통계용 커스텀 interceptor를 직접 만든다. — 레슨 0020
WHIP / WHEP
WebRTC 표준이 비워둔 시그널링을 스트리밍용으로 메운 HTTP 프로토콜 — offer를 POST(application/sdp)로 보내면 answer가 응답으로 온다. ingest 방향이 WHIP(RFC 9725), 재생 방향이 WHEP. OBS→mediamtx 연결이 이 방식이다. — 레슨 0020
replace 지시자 (go.mod)
"이 모듈을 요구하면 실제로는 저걸 써라"는 go.mod의 치환 문법. 포크 선탑재(LiveKit의 livekit/webrtc-pion -warp.N)나 로컬 경로 개발에 쓴다. — 레슨 0020
