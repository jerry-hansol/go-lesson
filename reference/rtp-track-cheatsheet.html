RTP·Track 치트시트

RTP 헤더 읽는 법과 pion v4 Track API 골격. 출처: WebRTC for the Curious ch.5·ch.6, pion/webrtc v4.

RTP 헤더 필드

필드크기푸는 문제읽는 법
SSRC32bit스트림(소스) 구분트랙마다 무작위 고유값 — 절대값 자체가 ID
sequence number16bit유실 감지·재정렬Δ+1이 정상. 구멍 = 유실. 시작값 난수, 65535 다음은 0 (랩어라운드)
timestamp32bit재생 타이밍·립싱크미디어 클럭 틱. 시작값 난수 — 절대값 말고 Δ를 본다
payload type7bit코덱 식별SDP a=rtpmap이 연결마다 계약한 번호 (동적: 96~127)

보내기 — Track API 선택

타입입력 단위seq·ts 계산용도
TrackLocalStaticSample인코딩된 프레임 + Durationpion이 대신파일 재생, 인코더 출력 송신 (대부분)
TrackLocalStaticRTPRTP 패킷 그대로내가 책임SFU 포워딩, RTSP→WebRTC 중계
track, _ := webrtc.NewTrackLocalStaticSample(
    webrtc.RTPCodecCapability{MimeType: webrtc.MimeTypeVP8}, "video", "stream-id")
pc.AddTrack(track)                    // 반드시 offer 생성 전!
track.WriteSample(media.Sample{Data: frame, Duration: time.Second / 30})

받기 — OnTrack 골격

pc.OnTrack(func(remote *webrtc.TrackRemote, _ *webrtc.RTPReceiver) {
    // 첫 RTP 패킷이 "도착했을 때" 불린다 (협상 완료 시점 아님)
    for {
        pkt, _, err := remote.ReadRTP()   // *rtp.Packet
        if err != nil { return }           // 트랙 종료 시 에러로 루프 탈출
        _ = pkt.SSRC; _ = pkt.SequenceNumber; _ = pkt.Timestamp
    }
})

미디어가 안 나올 때 체크리스트

  • AddTrack이 offer 생성 전인가? 협상 후 추가면 WriteSample이 에러 없이 버려진다 (실측: 90프레임 전송, OnTrack 0회) → 재협상 필요
  • 공통 코덱이 있는가? 없으면 answer 적용 시점에 unable to start track, codec is not supported by remote (실측, pc1의 SetRemoteDescription에서)
  • 상대가 실제로 보내고 있는가? OnTrack은 첫 패킷 도착 트리거 — 협상만 되고 송신이 없으면 영영 안 불린다
  • 기본 코덱 목록은 MediaEngine.RegisterDefaultCodecs — webrtc.NewPeerConnection은 이미 포함, 커스텀 NewAPI(WithMediaEngine(m))은 직접 등록
