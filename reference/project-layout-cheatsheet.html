Go 프로젝트 레이아웃 치트시트

멀티 패키지 모듈의 표준 구조. 출처: Organizing a Go module, How to Write Go Code.

표준 트리

mediakit/                        ← 모듈 루트 (go.mod: module mediakit)
├── go.mod
├── cmd/
│   ├── streamctl/main.go        ← 바이너리 1 (package main)
│   └── mediaprobe/main.go       ← 바이너리 2 — 나란히 추가
├── internal/
│   └── segment/segment.go       ← 외부 모듈 import 시 컴파일 에러
└── (외부 공개 라이브러리는 루트나 pkg/ — pkg/는 선택 관례)

import 경로 규칙

상황규칙
경로 구성모듈 경로 + 디렉토리 경로: mediakit/internal/segment
같은 모듈 내부go.mod 선언 없이 바로 import
패키지 이름디렉토리 이름과 같게 (관례). 사용은 segment.SplitSegments()
상대 경로모듈 모드에서 쓰지 않는다 (./x import 금지)
로컬 모듈 참조go.mod에 replace mediakit => ../mediakit (개발용)

경계 규칙

수단효과강제 주체
대문자 식별자패키지의 public API컴파일러 (밖에서 소문자는 undefined)
internal/부모 트리 밖에서 import 불가 — use of internal package ... not allowed컴파일러
cmd/<이름>/바이너리별 진입점. 실행은 go run ./cmd/streamctl관례

실제 저장소 사례 (미션 도메인)

저장소구조읽는 법
