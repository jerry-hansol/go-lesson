리뷰어라면 지적할 것 — 스스로에게 먼저

  • 에러 응답 형식이 일관적인가? 지금은 텍스트(http.Error) — 실서비스라면 JSON 에러 바디로 통일할 것.
  • 종료 시 큐에 남은 작업은? 현재 설계는 ctx 취소 시 채널에 남은 Job을 버린다. 유실이 허용되는가? 아니라면 close 후 드레인 패턴으로.
  • Jobs 채널이 가득 차면? 버퍼 64가 차면 POST 핸들러가 블록된다 — 요청 지연으로 전파된다. 타임아웃 또는 거절(429) 정책 후보.
  • 뮤텍스 경합 — Totals가 전체 맵을 순회하며 잠금을 잡는다. 스트림이 수만 개면? (카운터 분리 후보)
  • 테스트가 store에만 있다 — worker와 핸들러는? (핸들러 테스트는 httptest — 0009 참조)
