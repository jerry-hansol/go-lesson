ICE 치트시트 — candidate, STUN/TURN, pion 설정

출처: WebRTC for the Curious — Connecting, pion/webrtc v4. 실측 기준: v4.2.18.

candidate 4종

타입정체어디서 오나비용
hostNIC 주소 그대로로컬 인터페이스 열거0 — 같은 망이면 최선
srflxNAT 밖에서 보이는 공인 주소STUN 응답거의 0 (조회만)
prflx연결 검사 중 역발견된 상대 주소수신 검사 패킷의 출발지0 (부산물)
relay중계 서버 주소TURN 할당미디어 대역폭 전체

ICE 연결 상태 전이 (실측 경로)

new → checking → connected (→ completed) → closed, 실패·유실 시 disconnected / failed. pion에서는 OnICEConnectionStateChange로 관찰한다.

pion 설정 골격

config := webrtc.Configuration{
	ICEServers: []webrtc.ICEServer{
		{URLs: []string{"stun:stun.l.google.com:19302"}},
		// TURN은 자격 증명 필요:
		// {URLs: []string{"turn:turn.example.com:3478"}, Username: "u", Credential: "p"},
	},
}

// trickle 중계 (시그널링 서버가 하는 일)
pc.OnICECandidate(func(c *webrtc.ICECandidate) {
	if c != nil {
		// c.ToJSON()을 상대에게 전달 → 상대는 AddICECandidate
	}
})

// 진단: 실제 선택된 pair 확인
pair, _ := pc.SCTP().Transport().ICETransport().GetSelectedCandidatePair()

함정과 진단 (전부 실측)

증상원인/도구
srflx가 안 나온다STUN 주소 오타·UDP 차단 — 에러 없이 조용히 host만 나온다. PION_LOG_DEBUG=all로 Failed to resolve STUN host 류를 발굴
candidate를 한 방향만 전달했는데 연결됨정상 — 검사 패킷 출발지에서 prflx 역발견. 단, 대칭 NAT 실전에서는 양방향 교환+TURN 폴백 필수
checking에서 오래 머묾trickle 미사용(수집 완료 대기) 또는 검사 패킷이 도달 불가 — TURN 검토
연결은 되는데 비용 급증relay pair 비율 확인 — GetSelectedCandidatePair로 집계
