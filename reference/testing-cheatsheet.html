Go 테스트 치트시트

테이블 드리븐 골격과 go test 플래그. 출처: Using Subtests and Sub-benchmarks, Go by Example: Testing and Benchmarking.

규칙 (이게 전부)

  • 파일: xxx_test.go — 대상 코드와 같은 디렉토리, 같은 패키지
  • 함수: func TestXxx(t *testing.T) — 어노테이션·러너·assert 라이브러리 없음
  • 실행: go test ./...

테이블 드리븐 골격 (회사 컨벤션 표준)

func TestParse(t *testing.T) {
    tests := []struct {
        name string      // 서브테스트 이름 (한글 가능, 공백 대신 _)
        in   string
        want int
    }{
        {name: "정상", in: "6", want: 6},
        {name: "경계", in: "0", want: 0},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := Parse(tt.in)
            if got != tt.want {
                t.Errorf("got %d, want %d", got, tt.want)
            }
        })
    }
}

에러를 반환하는 함수는 테이블에 wantOK bool(성공 기대 여부)과 wantIs error(기대 원인)를 두고, errors.Is(err, tt.wantIs)로 원인까지 검증한다 — 전체 예제는 레슨 0009.

t의 메서드

메서드효과언제
t.Errorf(...)실패 기록 후 계속 진행기본값 — 남은 검사도 의미 있을 때
t.Fatalf(...)그 (서브)테스트 즉시 중단이후 검사가 무의미할 때 (전제 실패)
t.Run(name, fn)서브테스트 실행테이블의 케이스마다
t.Skip(...)테스트 건너뛰기환경 조건이 안 맞을 때

실패 메시지 어휘: 실제 값 got, 기대값 want, 순서도 got X, want Y.

go test 플래그

플래그하는 일
-v서브테스트까지 케이스별 RUN/PASS 출력
-run 'TestParse/케이스명'이름 매칭(정규식)으로 골라 실행 — 실패 케이스 하나만 반복할 때
-cover문장 커버리지 % 출력
-coverprofile=cover.out프로파일 저장 → go tool cover -func=cover.out(함수별 %) / -html=cover.out(안 밟은 줄 색칠)
-count=1테스트 캐시 무시 (코드 변경 없으면 ok ... (cached)가 뜬다)

흔한 함정

  • 커버리지 100% ≠ 버그 없음. 하지만 커버리지 구멍 = 확실히 검증 안 된 분기 — 숫자보다 "안 밟은 분기 찾기"에 쓴다.
  • 에러 케이스에서 성공 검사(got/want 비교)로 넘어가지 말 것 — Fatalf로 끊거나 return.
  • 서브테스트 이름의 공백은 -run 매칭 시 _로 바뀐다 — 처음부터 _로 짓는 게 편하다.
