Go 동시성 치트시트 — 고루틴·채널·WaitGroup

출처: Effective Go — Concurrency, Go by Example. 슬로건: "메모리를 공유해서 통신하지 말고, 통신해서 메모리를 공유하라."

기본 연산

코드뜻Java로 치면
go f(x)새 고루틴에서 f 실행 (기다리지 않음)executor.submit — 단, 언어 키워드
make(chan T)unbuffered 채널 — 송수신이 만나야 진행SynchronousQueue
make(chan T, n)버퍼 n짜리 채널 — 버퍼 차면 송신 블록BlockingQueue
ch <- v송신 (수신자/버퍼 자리 날 때까지 블록)queue.put
v := <-ch수신 (값 올 때까지 블록)queue.take
v, ok := <-ch수신 + 채널이 닫혔는지 확인 (닫힘 = ok가 false)—
close(ch)"더 안 보낸다" 선언 — 생산자만, 한 번만—
for v := range ch닫히고 소진될 때까지 수신—
wg.Add(1) / Done() / Wait()완료 카운터 (Add는 go 띄우기 전에)CountDownLatch

팬아웃 → 수집 패턴 (검증된 뼈대)

results := make(chan string)
var wg sync.WaitGroup

for id := 1; id <= n; id++ {
    wg.Add(1)                    // go 띄우기 전에 Add
    go func() {
        defer wg.Done()          // 어떤 경로로 끝나든 반드시 Done
        results <- work(id)
    }()
}

go func() {                      // 클로저(closer) 고루틴:
    wg.Wait()                    // 전원 완료를 기다렸다가
    close(results)               // 채널을 닫는다 — range 종료 조건
}()

for r := range results {         // main은 결과를 소진
    fmt.Println(r)
}

루프 변수 클로저 캡처는 Go 1.22+에서 안전(반복마다 새 변수). 옛 코드베이스는 go func(id int){...}(id)로 인자 전달한다.

흔한 사고와 증상

사고증상원인·처방
main 조기 종료출력 없음, 에러도 없음 (가장 위험)main은 고루틴을 안 기다린다 → WaitGroup/채널 수신으로 대기
전원 블록fatal error: all goroutines are asleep - deadlock! + [chan send]/[chan receive] 스택수신자 없는 송신, close 안 된 채널 range 등. 스택의 대괄호가 멈춘 지점
닫힌 채널 송신panic: send on closed channel닫는 쪽은 생산자 하나로 고정
이중 closepanic: close of closed channel위와 동일 — close 책임자를 한 곳으로
nil 채널 사용영원히 블록 (zero value 채널)var ch chan T만 하고 make를 잊음

언제 뭘 쓰나

  • 완료만 기다리면 → WaitGroup
  • 결과·데이터를 넘겨야 하면 → 채널
  • 여러 채널을 동시에 기다리면 → select (심화 레슨 예정)
  • 공유 변수에 락이 꼭 필요한 경우의 sync.Mutex도 있다 — 단, 채널로 풀 수 있으면 채널 먼저
