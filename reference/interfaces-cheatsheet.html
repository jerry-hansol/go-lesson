정의와 구현

type Publisher interface {          // 정의: 메서드 셋만 나열
    Publish(data string) error
}

type LogPublisher struct{ Prefix string }

func (p LogPublisher) Publish(data string) error {  // 이 메서드가 있으면
    ...                                             // LogPublisher는 Publisher다
}                                                   // implements 선언 없음
  • 암묵적 구현: 메서드 셋이 맞으면 자동 구현. 남의 패키지 타입도 내 인터페이스를 만족할 수 있다.
  • 포인터 리시버 메서드는 *T의 메서드 셋에만 들어간다 → &CountPublisher{}처럼 포인터로 넘긴다.
  • 구현이 안 맞으면 컴파일 에러: does not implement ... (wrong type for method ...) + have/want 비교.

표준 라이브러리의 축 — io.Reader / io.Writer

type Reader interface {
    Read(p []byte) (n int, err error)
}
type Writer interface {
    Write(p []byte) (n int, err error)
}

파일·소켓·HTTP 바디·압축 스트림이 전부 이 둘로 통한다. 미디어 서버 = Reader→Writer 파이프라인.

func (s Stream) String() string { return fmt.Sprintf("[%s]...", ...) }

설계 관례

  • 작게 — 메서드 1~2개짜리 인터페이스가 이상적. 큰 인터페이스는 냄새.
  • 사용하는 쪽에 정의 — 인터페이스는 구현 패키지가 아니라 그것을 소비하는 패키지에 둔다.
  • 인터페이스를 받고, 구조체를 반환 — 함수 파라미터는 인터페이스로 느슨하게, 반환은 구체 타입으로.
