pion 포워딩 골격

// 인그레스: 발행자 트랙 수신 → 이그레스 트랙들에 복제
sfuIn.OnTrack(func(remote *webrtc.TrackRemote, _ *webrtc.RTPReceiver) {
    for {
        pkt, _, err := remote.ReadRTP()
        if err != nil {
            return // 발행자 이탈 → EOF. 구독자 정리는 SFU의 책임
        }
        for _, out := range outputs { // 구독자별 TrackLocalStaticRTP
            _ = out.WriteRTP(pkt)
        }
    }
})

// 이그레스 sender마다 RTCP 소비 고루틴 — 반드시
sender, _ := pcOut.AddTrack(localTrack)
go func() {
    for {
        if _, _, err := sender.ReadRTCP(); err != nil {
            return
        }
    }
}()
  • TrackLocalStaticRTP의 "Static": seq·timestamp는 그대로 통과, SSRC·PT는 연결별 협상값으로 자동 재작성.
  • 구독자(클라이언트)당 PeerConnection 1개 — 미니어처든 LiveKit이든 같다.

사고 대응표 (전부 실측)

증상원인처방
단기간 무증상, 장기 운영에서 손실 복구·통계 죽음sender RTCP를 아무도 안 읽음sender마다 RTCP 소비 고루틴 (조용한 버그 — 데모에선 안 보인다)
SFU ReadRTP가 EOF발행자 PC Close/이탈정상 신호 — 구독자에게 해체를 전파하는 건 SFU 책임
구독자 초반 몇 패킷 유실파이프 준비 전 도착정상 (RTP는 손실 허용) — 화면 복구는 PLI로
구독자마다 SSRC가 다름연결별 SSRC 협상·재작성버그 아님 — seq·timestamp 통과 여부로 복제를 판단
