Lesson 0006 · Go 기초

인터페이스 — implements 없는 다형성

MediaMTX와 LiveKit 코드를 읽다 보면 온통 인터페이스다. Go 인터페이스는 Java와 문법이 아니라 철학이 다르다 — 선언이 아니라 구조로 만족한다. 예상 소요: 35–40분.

오늘의 목표 (하나만)

Publisher 인터페이스 하나에 구현 두 개를 갈아끼우는 코드를 직접 작성하고, Java와 다른 지점 세 곳(암묵적 구현, 작은 인터페이스, 타입 단언)을 설명할 수 있다.

1. 암묵적 구현 — implements가 없다

Java에서는 class LogPublisher implements Publisher라고 선언해야 구현이다. Go에서는 인터페이스가 요구하는 메서드를 전부 갖추면 그걸로 끝이다. 선언 없음, import조차 필요 없음 (Go by Example: Interfaces):

type Publisher interface {
    Publish(data string) error
}

type LogPublisher struct{ Prefix string }

// 이 메서드가 존재하는 순간 LogPublisher는 Publisher다. 선언 불필요.
func (p LogPublisher) Publish(data string) error {
    fmt.Println(p.Prefix, data)
    return nil
}

이게 왜 강력한가: 인터페이스를 사용하는 쪽이 정의할 수 있다. 남의 패키지 타입도, 내가 만든 인터페이스의 메서드 셋만 맞으면 그대로 받아 쓸 수 있다 — Java라면 어댑터 클래스를 만들어야 하는 상황이다.

2. 작은 인터페이스 — 메서드 1개가 표준이다

Java 인터페이스는 메서드 수십 개짜리가 흔하지만, Go 표준 라이브러리의 근간은 메서드 1개짜리다 (io.Reader / io.Writer):

type Reader interface {
    Read(p []byte) (n int, err error)
}
type Writer interface {
    Write(p []byte) (n int, err error)
}

파일, 네트워크 소켓, HTTP 바디, 압축 스트림이 전부 이 두 개로 통한다. 미디어 서버는 본질적으로 Reader→Writer 파이프라인이다 — RTMP 소켓에서 읽어(Read) 세그먼트 파일에 쓰는(Write) 코드가 MediaMTX 전체를 관통한다. 이 두 인터페이스가 눈에 익으면 미디어 서버 코드의 절반은 읽힌다.

3. fmt.Stringer — Go의 toString()

String() string 메서드를 붙이면 fmt.Println이 그 출력을 쓴다. Java의 toString() 재정의와 같은 역할인데, 이것도 암묵적 구현의 사례다 — fmt 패키지가 정의한 Stringer 인터페이스를 내 타입이 저절로 만족하는 것 (Go by Example: String Formatting):

func (s Stream) String() string {
    return fmt.Sprintf("[%s] %s %dkbps", state, s.Name, s.BitrateKbps)
}

4. 타입 단언 — instanceof의 대응물

인터페이스 값에서 구체 타입을 꺼낼 때는 v, ok := i.(T). Java의 instanceof 검사 + 캐스팅이 한 줄로 합쳐진 형태다:

lp, ok := p.(LogPublisher)   // 맞으면 ok=true, lp에 구체 값
cp, ok := p.(*CountPublisher) // 틀리면 ok=false, cp는 zero value(nil)
bad := p.(*CountPublisher)   // ok 없이 쓰면 — 실패 시 panic!

, ok가 있는 형태가 레슨 0002의 다중 반환 패턴 그대로라는 점에 주목. 실무에서는 거의 항상 , ok 형태를 쓴다.

5. 실습 — Publisher 갈아끼우기

  1. playground/interfaces 디렉토리를 만들고 go mod init interfaces 후 main.go 작성: 
    package main

import "fmt"

// Publisher는 메시지를 내보내는 대상 — 구현이 무엇이든 상관하지 않는다.
type Publisher interface {
	Publish(data string) error
}

// LogPublisher는 받은 메시지를 표준 출력에 찍는다.
type LogPublisher struct {
	Prefix string
}

func (p LogPublisher) Publish(data string) error {
	fmt.Println(p.Prefix, data)
	return nil
}

// CountPublisher는 발행 횟수만 센다 — 테스트 더블의 원형.
type CountPublisher struct {
	Count int
}

func (p *CountPublisher) Publish(data string) error {
	p.Count++
	return nil
}

// broadcast는 Publisher가 구체적으로 무엇인지 모른 채 메시지를 내보낸다.
func broadcast(p Publisher, msgs []string) {
	for _, m := range msgs {
		if err := p.Publish(m); err != nil {
			fmt.Println("발행 실패:", err)
		}
	}
}

// Stream은 fmt.Stringer를 구현한다 — String() 하나면 Println 출력이 바뀐다.
type Stream struct {
	Name        string
	BitrateKbps int
	Live        bool
}

func (s Stream) String() string {
	state := "종료"
	if s.Live {
		state = "LIVE"
	}
	return fmt.Sprintf("[%s] %s %dkbps", state, s.Name, s.BitrateKbps)
}

func main() {
	msgs := []string{"segment-001.ts", "segment-002.ts", "segment-003.ts"}

	log := LogPublisher{Prefix: "publish:"}
	broadcast(log, msgs)

	counter := &CountPublisher{}
	broadcast(counter, msgs)
	fmt.Println("발행 횟수:", counter.Count)

	s := Stream{Name: "ebay-live-42", BitrateKbps: 2500, Live: true}
	fmt.Println(s)
}

    예상 출력:

    publish: segment-001.ts
publish: segment-002.ts
publish: segment-003.ts
발행 횟수: 3
[LIVE] ebay-live-42 2500kbps

    같은 broadcast 함수에 LogPublisher와 &CountPublisher{}가 모두 들어간다 — 이게 다형성이다. CountPublisher가 포인터로 전달되는 이유는 레슨 0005 그대로: Count를 변경해야 하니 포인터 리시버이고, 포인터 리시버 메서드는 *CountPublisher만 갖는다.

부숴보기 — 컴파일러와 panic이 하는 말 읽기

  1. LogPublisher의 메서드 시그니처를 Publish(data []byte) error로 바꾸고 go run .

    예상:

    cannot use log (variable of struct type LogPublisher) as Publisher value
  in argument to broadcast: LogPublisher does not implement Publisher
  (wrong type for method Publish)
		have Publish([]byte) error
		want Publish(string) error

    have/want 두 줄이 핵심이다 — 암묵적 구현이라 "선언이 빠졌다"가 아니라 "메서드 셋이 안 맞는다"고 말한다. 실무에서 자주 만날 에러이니 형태를 눈에 익혀두자. 확인 후 원상복구.

  2. main 끝에 다음을 추가하고 실행: 
    var p Publisher = LogPublisher{Prefix: ">"}
cp, ok := p.(*CountPublisher)
fmt.Println("CountPublisher?", ok, cp)

bad := p.(*CountPublisher) // ok 없는 단언
fmt.Println(bad)

    예상: , ok 형태는 CountPublisher? false <nil>로 조용히 알려주지만, ok 없는 단언은 즉시 죽는다:

    panic: interface conversion: main.Publisher is main.LogPublisher, not *main.CountPublisher

    런타임 panic의 생김새를 처음 보는 순간이다 — Java의 ClassCastException 스택트레이스에 해당한다. 확인 후 추가분 삭제하고 go fmt ./....
