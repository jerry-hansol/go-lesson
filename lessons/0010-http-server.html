Lesson 0010 · Go 실전

net/http — 표준 라이브러리만으로 API 서버

Spring Boot 없이, 프레임워크 없이. 표준 라이브러리만으로 라우팅·JSON·에러 응답을 갖춘 API 서버를 띄운다 — 그리고 이게 Go 문화의 기본값이다. 개념 셋: 패턴 라우팅, JSON 인코딩/디코딩, 에러 응답. 예상 소요: 40분.

오늘의 목표 (하나만)

스트림 목록·단건 조회·등록을 처리하는 REST API 서버를 표준 라이브러리만으로 띄우고, curl로 200/201/400/404/405를 전부 직접 확인한다.

1. 핸들러와 패턴 라우팅 — @RestController의 자리

Go의 핸들러는 어노테이션 붙은 메서드가 아니라 그냥 함수다: func(w http.ResponseWriter, r *http.Request). 라우팅은 http.ServeMux가 맡고, Go 1.22부터 메서드와 경로 와일드카드를 패턴으로 쓴다 (Routing Enhancements for Go 1.22):

mux := http.NewServeMux()
mux.HandleFunc("GET /streams", listStreams)         // 메서드 매칭
mux.HandleFunc("GET /streams/{id}", getStream)      // 와일드카드
mux.HandleFunc("POST /streams", createStream)

id := r.PathValue("id")                             // 핸들러 안에서 {id} 꺼내기
  • 패턴에 없는 메서드로 오면 ServeMux가 405 + Allow 헤더를 자동으로 응답한다 — 실습에서 확인.
  • 옛 코드에서는 http.HandleFunc("/streams", h) + 핸들러 안 r.Method 분기, 또는 gorilla/mux·chi 같은 서드파티 라우터를 보게 된다 — 1.22 이후 새 코드는 표준만으로 충분한 경우가 많다.

2. JSON — Jackson의 자리엔 encoding/json

type Stream struct {
    ID          string `json:"id"`            // struct 태그가 JSON 키를 정한다
    Codec       string `json:"codec"`
    BitrateKbps int    `json:"bitrate_kbps"`
}

json.NewEncoder(w).Encode(s)       // 응답에 바로 직렬화 (w는 io.Writer — 레슨 0006!)
json.NewDecoder(r.Body).Decode(&s) // 요청 바디에서 역직렬화
  • 태그가 없으면 JSON 키는 필드명 그대로(ID, BitrateKbps) — snake_case가 필요하면 태그 필수 (Go by Example: JSON).
  • 함정: 소문자(unexported) 필드는 에러 없이 조용히 직렬화에서 빠진다. 레슨 0002의 대문자=공개 규칙이 여기서 물어뜯는다 — 부숴보기에서 재현.
  • Encoder/Decoder가 io.Writer/io.Reader를 받는다는 것에 주목 — 레슨 0006에서 배운 작은 인터페이스가 응답 스트림에 그대로 꽂히는 현장이다.

3. 에러 응답 — http.Error와 return

if !ok {
    http.Error(w, fmt.Sprintf("stream %q not found", id), http.StatusNotFound)
    return // ← 생략하면 아래 코드가 계속 실행돼 응답이 섞인다
}

http.Error는 상태코드와 text/plain 바디(+ X-Content-Type-Options: nosniff)를 쓴다. 상태코드는 http.StatusNotFound 같은 상수로. 핸들러는 예외로 중단되지 않으므로(레슨 0003 — 에러는 값), 에러 응답 후 return은 본인 책임이다.

4. 실습 — 스트림 API 서버

  1. playground/streamapi를 만들고 go mod init streamapi 후 main.go 작성: 
    package main

import (
	"encoding/json"
	"fmt"
	"log"
	"net/http"
)

// Stream은 API가 다루는 스트림 리소스다.
type Stream struct {
	ID          string `json:"id"`
	Codec       string `json:"codec"`
	BitrateKbps int    `json:"bitrate_kbps"`
}

// 메모리 저장소 — 동시성 안전하지 않다 (레슨 0012에서 이 레이스를 직접 잡는다).
var streams = map[string]Stream{
	"live-1": {ID: "live-1", Codec: "h264", BitrateKbps: 2500},
}

// listStreams는 등록된 스트림 전체를 JSON 배열로 응답한다.
func listStreams(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	list := make([]Stream, 0, len(streams))
	for _, s := range streams {
		list = append(list, s)
	}
	json.NewEncoder(w).Encode(list)
}

// getStream은 경로 와일드카드 {id}로 단건을 조회한다. 없으면 404.
func getStream(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	s, ok := streams[id]
	if !ok {
		http.Error(w, fmt.Sprintf("stream %q not found", id), http.StatusNotFound)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(s)
}

// createStream은 요청 바디의 JSON을 디코드해 등록한다. 잘못된 입력은 400.
func createStream(w http.ResponseWriter, r *http.Request) {
	var s Stream
	if err := json.NewDecoder(r.Body).Decode(&s); err != nil {
		http.Error(w, "잘못된 JSON: "+err.Error(), http.StatusBadRequest)
		return
	}
	if s.ID == "" {
		http.Error(w, "id는 필수다", http.StatusBadRequest)
		return
	}
	streams[s.ID] = s
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	json.NewEncoder(w).Encode(s)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /streams", listStreams)
	mux.HandleFunc("GET /streams/{id}", getStream)
	mux.HandleFunc("POST /streams", createStream)

	log.Println("listening on :8080")
	log.Fatal(http.ListenAndServe(":8080", mux))
}
  2. 터미널 1에서 go run .

    예상: listening on :8080 로그 후 대기.

  3. 터미널 2에서 curl 시나리오를 순서대로 (아래는 전부 실측 출력): 
    $ curl -s localhost:8080/streams
[{"id":"live-1","codec":"h264","bitrate_kbps":2500}]

$ curl -s localhost:8080/streams/live-1
{"id":"live-1","codec":"h264","bitrate_kbps":2500}

$ curl -si localhost:8080/streams/nope | head -1
HTTP/1.1 404 Not Found            # 바디: stream "nope" not found

$ curl -si -X POST localhost:8080/streams \
    -d '{"id":"live-2","codec":"av1","bitrate_kbps":4000}' | head -1
HTTP/1.1 201 Created              # 바디: 등록된 스트림 JSON

$ curl -s localhost:8080/streams   # live-2가 목록에 추가됨
[{"id":"live-1",...},{"id":"live-2","codec":"av1","bitrate_kbps":4000}]

$ curl -si -X DELETE localhost:8080/streams | head -2
HTTP/1.1 405 Method Not Allowed
Allow: GET, HEAD, POST            # ServeMux가 자동으로 응답

부숴보기 — 세 가지

  1. 깨진 JSON을 쏴보기: curl -si -X POST localhost:8080/streams -d '{broken'

    실측: HTTP/1.1 400 Bad Request + 잘못된 JSON: invalid character 'b' looking for beginning of object key string — Decode의 error 반환값(레슨 0003)이 그대로 방어선이 된다.

  2. 필드를 소문자로: Codec을 codec으로 전부 바꾸고 재시작, GET /streams/live-1

    실측: {"id":"live-1","bitrate_kbps":2500} — 에러 없이 codec 필드만 조용히 증발했다. 그리고 go vet ./...를 돌리면 struct field codec has json tag but is not exported로 잡아준다 — vet을 CI에 두는 이유. 확인 후 복구.

  3. WriteHeader 이후 http.Error: getStream 맨 위에 w.WriteHeader(http.StatusOK)를 추가하고 /streams/nope 호출

    실측: 클라이언트는 HTTP/1.1 200 OK에 바디는 stream "nope" not found — 404가 도달하지 못한다! 서버 로그에만 http: superfluous response.WriteHeader call from main.getStream (main.go:38). 상태코드는 첫 WriteHeader가 확정하고 이후 호출은 로그만 남긴다. 확인 후 복구.
