Lesson 0004 · Go 기초

슬라이스와 맵 — Go의 컬렉션

ArrayList와 HashMap의 자리를 Go에서는 슬라이스와 맵이 차지한다 — 단, 내부 동작이 눈에 보이는 방식으로. 개념 셋: 슬라이스, 맵과 comma ok, for range. 예상 소요: 35–40분.

오늘의 목표 (하나만)

비트레이트 샘플의 평균·최대와 코덱별 카운트를 슬라이스·맵으로 계산하고, 슬라이스가 배열을 공유하는 창(view)이라는 것과 맵의 comma ok 관용구를 설명할 수 있다.

1. 슬라이스 — 배열 위에 얹힌 창

Go의 배열([4]int)은 크기가 타입의 일부라 실무에서 직접 쓸 일이 드물다. 대신 슬라이스([]int)를 쓴다 — 배열을 가리키는 (포인터, 길이 len, 용량 cap) 세 값짜리 가벼운 구조다 (Go Slices: usage and internals).

samples := []int{2400, 3100, 2800}      // 슬라이스 리터럴
s := make([]int, 0, 4)                  // len 0, cap 4로 생성
s = append(s, 1, 2, 3)                  // len 3, cap 4
s = append(s, 4, 5)                     // cap 초과 → 더 큰 배열로 복사, len 5, cap 8
  • append는 재할당할 수 있으므로 반환값을 반드시 받는다: s = append(s, x). ArrayList의 add()처럼 제자리 수정이 보장되지 않는다.
  • s[1:3] 슬라이싱은 복사가 아니라 같은 배열을 보는 창이다 — 부숴보기에서 직접 확인한다.
  • nil 슬라이스도 len 0, append, range 모두 안전하다. var s []int로 시작해도 된다.

2. 맵 — comma ok가 필수인 이유

codecs := make(map[string]int)   // 쓰려면 make (또는 리터럴)가 필수
codecs["h264"]++                 // 없는 키면 zero value 0에서 시작 — 카운팅이 한 줄
delete(codecs, "h264")

n, ok := codecs["vp9"]           // comma ok 관용구: 값과 "키 존재 여부"를 함께

Java에서 map.get(k) == null로 부재를 확인하지만, Go는 없는 키를 읽으면 에러 없이 zero value가 나온다(레슨 0002). 그래서 "값이 0인 키"와 "없는 키"를 구분하려면 v, ok :=가 유일한 방법이다 (Go by Example: Maps).

한 가지 함정 예방: range로 맵을 순회하는 순서는 의도적으로 무작위다. fmt.Println 출력이 정렬돼 보이는 건 fmt가 보기 좋게 정렬해 주는 것뿐이다.

3. for range — 루프는 for 하나뿐

Go에는 while도 do-while도 없다. 루프는 for 하나이고, 컬렉션 순회는 range 형태를 쓴다 (Go by Example: Range):

for i, v := range samples { ... }   // 인덱스, 값
for _, v := range samples { ... }   // 값만 (인덱스는 _로 버림 — 레슨 0002)
for k, v := range codecs { ... }    // 키, 값 (순서 무작위!)
for i := 0; i < 10; i++ { ... }     // 전통 for. 조건만 쓰면 while처럼 동작

4. 실습 — 비트레이트 통계와 코덱 카운트

  1. playground/collections를 만들고 go mod init collections 후 main.go 작성: 
    package main

import "fmt"

func main() {
	// 5초마다 수집한 비트레이트 샘플 (kbps)
	samples := []int{2400, 3100, 2800, 4500, 3900}

	sum, max := 0, samples[0]
	for _, s := range samples {
		sum += s
		if s > max {
			max = s
		}
	}
	fmt.Println("평균:", sum/len(samples), "kbps / 최대:", max, "kbps")

	// 스트림별 코덱 카운트
	streams := []string{"h264", "h265", "h264", "av1", "h264"}
	codecs := make(map[string]int)
	for _, c := range streams {
		codecs[c]++
	}
	fmt.Println("코덱 분포:", codecs)

	n, ok := codecs["vp9"]
	fmt.Println("vp9 개수:", n, "/ 키 존재?", ok)
}

    예상 출력: 평균: 3340 kbps / 최대: 4500 kbps / 코덱 분포: map[av1:1 h264:3 h265:1] / vp9 개수: 0 / 키 존재? false

부숴보기 — 세 가지

  1. 맵을 make 없이 선언만 하고 쓰기: var m map[string]int 후 m["h264"] = 1

    예상: panic: assignment to entry in nil map — 첫 런타임 panic이다. nil 맵은 읽기(zero value)는 되지만 쓰기는 panic. nil 슬라이스는 append가 되는데 nil 맵은 안 되는 비대칭을 기억할 것. 확인 후 make로 복구.

  2. 슬라이스가 "창"이라는 증거: 
    orig := []int{2400, 3100, 2800, 4500}
head := orig[0:2]
head[0] = 9999
fmt.Println("orig:", orig)

head = append(head, 7777) // head의 cap이 남아 있어서...
fmt.Println("orig:", orig)

    실제 출력: orig: [9999 3100 2800 4500] → orig: [9999 3100 7777 4500]. 슬라이싱은 복사가 아니고, append가 남는 cap을 재사용하며 원본의 2800을 덮어썼다. 함수에 슬라이스를 넘길 때 이 공유가 버그의 단골 원인이다.

  3. 없는 키 읽기는 panic도 에러도 아니다: var m map[string]int(nil 맵)에서 fmt.Println(m["h264"])

    실제 출력: 0 — 조용히 zero value. 그래서 "존재 확인"은 반드시 comma ok로.
