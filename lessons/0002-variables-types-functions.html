변수·타입·함수 — Java 반사신경 덮어쓰기

레슨 0001이 쉬웠다고 하셔서 밀도를 올렸습니다. 이번엔 개념 셋: 선언과 zero value, 명시적 타입 변환, 다중 반환 함수. 예상 소요: 35–40분.

오늘의 목표 (하나만)

HLS 스트림의 세그먼트 개수를 계산하는 다중 반환 함수를 직접 작성하고, Java와 다르게 동작하는 지점 세 곳(zero value, 명시적 변환, _)을 설명할 수 있다.

1. 변수 선언 세 가지와 zero value

var bitrate int          // ① 선언만 — 자동으로 zero value(0)로 초기화된다
var codec = "h264"       // ② 초기값에서 타입 추론 (string)
segLen := 6              // ③ 짧은 선언 — 선언+초기화 한 번에. 함수 안에서만 가능

실무 Go 코드의 대부분은 ③ :=다. 단, :=는 선언이고 =는 대입 — 이미 있는 변수에 :=를 다시 쓰면 "no new variables" 에러가 난다.

Java와 결정적으로 다른 점: Go에는 "초기화 안 된 변수" 상태가 없다. 모든 변수는 선언 즉시 타입별 zero value를 갖는다 (Go by Example: Variables).

2. 타입 변환은 항상 명시적

Java의 암묵적 승격(int→long→double)이 Go에는 없다. 타입이 다르면 연산 자체가 컴파일 에러이고, 변환은 항상 T(v) 형태로 쓴다:

var total int = 95
ratio := float64(total) / 4.0   // OK — 명시적 변환
// bad := total / 4.0           // 컴파일 에러: mismatched types

귀찮아 보이지만, 미디어 코드에서 비트레이트·타임스탬프 계산할 때 정밀도 손실이 일어나는 지점이 코드에 전부 드러난다는 뜻이다.

3. 함수 — 타입은 뒤에, 반환은 여러 개

// splitSegments는 총 재생 시간(초)을 세그먼트 길이로 나눠
// 온전한 세그먼트 개수와 남는 초를 반환한다.
func splitSegments(totalSec, segLen int) (int, int) {
    return totalSec / segLen, totalSec % segLen
}
  • 타입이 이름 뒤에 온다: totalSec int. 같은 타입 파라미터는 totalSec, segLen int처럼 묶는다.
  • 반환값이 여러 개: (int, int). Java처럼 DTO나 Pair 클래스를 만들 필요가 없다 (Go by Example: Multiple Return Values).
  • 받을 때는 full, rem := splitSegments(95, 6). 하나가 필요 없으면 블랭크 식별자 _로 버린다: full, _ := ... — 안 쓰는 변수가 에러이기 때문에 "받고 방치"가 불가능하다.

예고: 이 다중 반환이 Go 에러 처리의 토대다. 표준 라이브러리 함수 대부분이 (값, error)를 반환한다 — 다음 레슨의 주인공.

4. 실습 — HLS 세그먼트 계산기

  1. playground/basics 디렉토리를 만들고 모듈 초기화 (go mod init basics) 후 main.go 작성: 
    package main

import "fmt"

// splitSegments는 총 재생 시간(초)을 세그먼트 길이로 나눠
// 온전한 세그먼트 개수와 남는 초를 반환한다.
func splitSegments(totalSec, segLen int) (int, int) {
	return totalSec / segLen, totalSec % segLen
}

func main() {
	total := 95 // 95초짜리 스트림
	full, rem := splitSegments(total, 6)
	fmt.Println("세그먼트:", full, "개, 마지막:", rem, "초")

	ratio := float64(rem) / float64(total) * 100
	fmt.Printf("남는 구간 비율: %.1f%%\n", ratio)
}

    예상 출력: 세그먼트: 15 개, 마지막: 5 초 / 남는 구간 비율: 5.3%. Printf는 C 스타일 포맷 동사(%d, %.1f 등)를 쓴다 — 목록은 문법 치트시트에.

부숴보기 — 이번엔 세 가지

  1. unused := 42 한 줄을 추가하고 go run .

    예상: declared and not used: unused — import와 동일한 철학. 확인 후 삭제.

  2. ratio 계산에서 float64(total)의 변환만 지우기: float64(rem) / total * 100

    예상: invalid operation: ... mismatched types float64 and int — 암묵적 승격이 없다는 걸 컴파일러가 증명한다. 원상복구.

  3. 이번엔 변환을 둘 다 지우기: rem / total * 100

    예상: 에러 없이 컴파일되고 0.0%가 나온다(rem/total이 정수 나눗셈으로 0). Java와 똑같은 함정이지만, Go에선 float 연산에 변환이 반드시 보이므로 "변환이 안 보이면 정수 연산"이라고 코드에서 바로 읽어낼 수 있다. 원상복구 후 go fmt ./...로 마무리.
